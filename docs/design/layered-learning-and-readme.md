# 分层问答、网站演示与项目入口

本次目标由三个完整交付组成，不能以部分论文或示例演示代替全量完成。

## 分层问答

基线为 1034 条论文/资料、1042 问，其中 1030 条只有一问。每条记录补齐四个层次：
`basics`（基础理解）、`mechanism`（核心机制）、`comparison`（方法对比）、
`implementation`（实现细节）。每层至少一问，每问保留直接答案、教学例子和本篇实际来源章节。
保留已有题目 ID 和加入日期；比较机制时不虚构实验胜负，实现问题区分原方法与本地证据。

页面按学习顺序展示，并提供层次筛选；同样支持主题、子主题、单篇论文和关键词组合。
问答深链会解除冲突筛选并展开答案。全部、最近新增和子主题使用同一来源。
发布检查要求每篇四层齐全，不能靠四个同类问题或自动摘要通过。

## README

主 README 保留项目定位、实时 CI 状态、网站功能、演示、最小安装与命令、文档导航和参与方式。
把安装/数据/平台示例、进化与外部实验、历史交付拆成 `readme_*.md`，保留原有命令和证据入口。
README 镜像脚本同时同步拆分文件、站内链接和媒体路径，避免站点链接失效。
维护状态由 CI、提交历史和保留的交付记录表达，不编造更新频率或路线承诺。

## 演示

制作不超过 60 秒的真实网站操作演示，保留 MP4 并转为动画 WebP 嵌入主 README。
展示论文查找、主题导航、四层问答、答案/例子/来源、最近新增和公开实验看板。
使用本次最终构建的实际画面；字幕说明用户能完成的操作，不伪造点击结果。
核对时长、动画帧、清晰度、体积和 GitHub/站点两处媒体链接。

## 验证与交付

- 逐条核对全量四层覆盖、旧 ID/日期不变、有效来源标题和重复/模板内容。
- 运行相关 pytest、生成一致性、README 同步与严格文档构建；真实浏览器核对筛选、深链和手机布局。
- 检查主 README 的所有拆分链接，以及 WebP 的实际播放和总时长。
- 通过适用 CI 后发布，并核对线上计数、资源和操作；保留验证回执，清理临时构建和编码中间产物。
