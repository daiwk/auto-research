# 持续维护的专题精读

把原来的两篇专题串读移出站点，改为现有六主题、31子主题各一张精读卡片。
逐篇四层问答继续独立维护；精读卡片负责跨论文的机制对照、取舍分析与问答。

## 内容与入口

每张卡片先提出一个共同问题，再比较至少三篇代表论文。对照表列出机制定位与取舍，
使用本地 README 的实际章节和原始论文链接。至少两段分析、三个跨论文问答，每问
提供直接答案与教学例子，并引用至少两篇本主题论文。没有统一实测协议时，只比较
机制、假设和适用场景，不给出性能排名。完整主题目录默认折叠，代表比较范围明确说明。

侧栏“专题精读”按六主题再折叠一层；汇总页默认只显示六个折叠分组。
逐篇问题库和精读卡片互相链接，学习首页的主题目录同时提供两个入口。
使用现有 Material 字体与配色，以安静的两栏主题卡片和机制对照表区分阅读层次；
手机缩成单栏，对照表按每篇资料纵向展示来源、机制与取舍，避免左右来回找列。

## 增量更新

人工内容保存在 `docs/learning/deep-dives/*.json`；渲染不调用模型，也不编造摘要问答。
`reviewed_papers` 是已核对摘要和归类的身份快照，必须等于对应 topic 的成员；它不表示
全部论文已精读。`updates` 按日期追加，覆盖涉及论文，最新日期与 `updated` 一致，论文对应更新不得早于其首次问答加入日期。
每条更新保存涉及 README 的 SHA256；旧来源正文或实现边界变化时，也要求复核并追加更新。新论文进入时，作者核对现有区分是否仍成立，必要时小改比较、分析或问答，并记录原因。
原问题 ID 和历史记录保留。生成检查要求每个 topic 都有卡片，且新论文有对应卡片更新。

## 验收

校验全量31卡、成员与更新日志覆盖、代表论文及来源标题、跨论文问答数量与稳定ID。
测试新增论文缺更新被拒绝、完整增量更新可通过、失败前不写生成文件。
运行相关文档测试、生成一致性、严格站点构建，并检查桌面/手机折叠导航、对照表与问答展开。
