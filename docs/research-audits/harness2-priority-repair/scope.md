# Harness² 与 Google/Meta 历史筛选补漏

本轮以用户点名的 Harness² 为入口，修复“窗口外发现记录被当作已完成方法审查”
的筛选漏洞；交付一个 MR，不推进未经完整核验的审查水位。

## 接受范围

1. 阅读 Harness² 原文与固定版本官方实现，保留双层递归和无 gold 的选择边界。
2. 实现 CPU 可执行的低成本核心组件及测试；明确区分 L1 机制诊断与真实模型能力。
3. 独立中文论文页、完整来源元数据、原图、分类目录、实测指标与可复跑命令。
4. 完整模型/API 基准标注“成本过高，不复现（审查 DONE）”，不下载大型资源或启动付费评测。
5. 修正发现去重、优先机构判定及审查写入门禁；添加 Harness² 类回归。
6. 对已保存的 Google/Meta 官方历史记录逐项对账，并回查近期官方目录；
   区分已收录、历史补漏、范围外和无法核实，记录实际核验范围，不声称全来源穷尽。
7. 运行适用质量门禁；检查 MR 分支、差异和 CI；清理本轮可重建临时产物。

## 资源与证据约束

- 当前 Harness² 核心编排不要求 CUDA。若补漏项新增 CUDA 实现，须在单张 A100/A30 上实跑。
- 发现/日期核对不等于方法审查；目录存在不等于实现；多种子机制诊断不等于能力比较。
- 冻结审查快照保留，新处置追加到发现账本；高成本终态不自动重试。
- 不修改运行模型默认值，不使用 DeepXiv，不重建 uv.lock。
