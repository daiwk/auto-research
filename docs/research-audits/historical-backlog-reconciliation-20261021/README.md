## 先纠正之前的表述

之前“历史都处理完”的说法不准确。完成的是选定的固定实现批次，以及有界窗口的审查处置；
不是所有历史候选都已实现。把审查水位、固定批次完成、候选接受和代码交付混在一起，造成了误导。
上轮未经完整对账便把 `54` 和 `521` 当成剩余待办汇总，也不够严谨。

这次按论文身份去重，再对照三份冻结审查登记、55批 ledger、当前 manifest、文档和实际实现检索，
并用官方作者块/资源配置优先核查 Google、Meta。**没有训练、没有下载模型或数据、没有启动 GPU，
只新增核查报告与复算材料，不改原 ledger、水位或运行时分类器。**

## 为什么以前会给出错误印象

1. **交付范围被扩大表述。** B00–B11是固定74篇；H01–H07是固定55篇。对应路线图只承诺这些批次，
   其余历史候选不是随批次自动完成。Oct07快照自身还明确写“接受、待实现494”。
2. **审查状态被当成实现状态。** 原消费逻辑只要在ledger出现就视为reviewed，后来的known继承继续遮住旧接受项。
3. **上轮修复仍用了不稳定的自由文本启发式。** “保留下一批参考”“下一批须核验”被算成implementation-pending；
   同时没有识别Oct15的接受resolution和“本轮未实现”，漏14项。
4. **机构目录年份/新增来源和论文首发混用。** 54包含9篇2026以前的论文，另有文体/范围不适合直接实施的项。
   `2511.02767`原审计日期还发生一次错标：官方v1是2025-11-04，不是2026-04-23。

这些是统计和汇报缺陷，不是代码已经完成、只是漏打勾；本轮未发现可据以把大量条目直接改为已实现的证据。
